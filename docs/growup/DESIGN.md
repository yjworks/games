# 커서 뭐 될래 — 설계서

초1부터 고3까지 12년(144달)을 키워 진로를 정하는 육성 시뮬레이션.
버튼 4개(①~④)만으로 끝까지 할 수 있게 만들었고, 웹 화면 · 파이브레인(240×320 컬러) · 파이보(128×64 흑백)가 **같은 엔진**을 쓰도록 나눴다.

---

## 1. 교육 설계

학교 진로교육에서 흔히 쓰는 네 영역(자기 이해 · 일과 직업세계 이해 · 진로 탐색 · 진로 설계와 준비)에
자기 관리·경제 감각을 더해, 게임 장치 하나하나를 학습 목표에 묶었다.
(공식 성취기준 문서와의 정확한 대응은 확인이 필요하다 — 아래는 게임 쪽 설계 의도다.)

| 영역 | 학습 목표 | 게임 장치 | 코드 |
|---|---|---|---|
| 자기 이해 | 내가 무엇을 좋아하는지 알아차린다 | 학년마다 **돌아보기 질문**("올해 가장 즐거웠던 일은?") — 고른 활동 분야의 관심이 조금 자란다 | `engine.reflect`, `flow` review |
| 자기 이해 | 흥미 유형을 말로 설명한다 | **진로흥미 6유형(RIASEC)** — 고등 진로 상담과 졸업 리포트에서 육각형 그래프로 | `edu.riasec`, `topRiasec` |
| 직업세계 이해 | 직업이 하는 일·되는 길·관련 과목을 안다 | **직업 퀴즈**(보기 4개 = 버튼 4개, 하는 일/관심 분야/관련 과목). 틀려도 직업 카드를 보여 준다 | `edu.makeQuiz`, `engine.answerQuiz` |
| 직업세계 이해 | 직업 형태가 여럿임을 안다 | 엔딩이 취업·창업·프리랜서·연구로 갈리고, 도감에 모인다 | `careers.ts` |
| 진로 탐색 | 다양한 경험이 선택지를 넓힘을 안다 | 장소 4곳 × 학교급 3단계 = 활동 48가지, 진로체험센터 "직업 체험"(무작위 분야) | `data.ts` |
| 진로 설계 | 목표와 지금 사이의 차이를 본다 | 졸업 리포트의 **"조금만 더 했다면 닿았을 길"** — 모자란 관심·능력·돈·성향을 숫자로 | `edu.nearMisses`, `careerNeeds` |
| 자기 관리 | 쉬는 것도 계획임을 안다 | 4주 진행에서 지치면 뒤 주가 실패, 너무 쌓이면 아파서 한 달을 쉰다. 돌아보기 조언 | `engine.odds`, `edu.yearTips` |
| 경제 | 수입·지출·저축을 기록한다 | **용돈 기입장**(학년별 들어온 돈·쓴 돈·남은 돈), 창업에는 모은 돈이 필요 | `YearStats`, `addMoney` |
| 관계 | 같은 관심사가 관계를 만든다 | 친구 4명의 친밀도·친구 사건·10년 뒤 이야기 | `friends.ts` |
| 표현 | 디지털 그림으로 나를 표현한다 | **픽셀 초상 편집기**(16·24·32칸, 좌우 대칭), 프리셋, 그림 올리기 | `PixelEditor.tsx`, `pixelart.ts` |

수업에서 쓰는 법(제안): 한 판(30~40분) → 졸업 리포트를 보며 "내 유형과 실제 나의 차이", "조금만 더 했다면 닿았을 길"을 짝과 이야기 → 실제 진로흥미검사(커리어넷 등)와 비교.

### 정확성 원칙
- 직업 카드(하는 일·되는 길)는 일반적인 경로만 적는다. 퀴즈는 카드 내용에서만 문제를 만든다(새 사실을 지어내지 않는다).
- 퀴즈 오답은 다른 분야 직업·겹치지 않는 과목에서 고른다(정답이 둘처럼 보이지 않게).
- RIASEC은 게임 활동으로 계산한 간이 유형이라고 화면에 밝힌다.

## 2. 엔진 구조

```
types.ts      상태(GameState)·보고서 자료형 — JSON 으로 저장된다(v4)
calendar.ts   턴 → 학년·월·방학
data.ts       장소 4곳 × 학교급 3 × 활동 4
careers.ts    직업 29개(하는 일·되는 길·10년 뒤 3단계·흥미 유형·관련 과목)
events.ts     사건 23개 / friends.ts 친구 4명과 친구 사건 8개
engine.ts     규칙: 4주 진행, 컨디션, 시험, 학년 정산, 사건, 퀴즈, 돌아보기, 진로 판정
edu.ts        교육 장치: RIASEC, 퀴즈 만들기, 돌아보기 조언, 모자란 것
flow.ts       ★ 진행 상태 기계: (Flow, GameState, 버튼) → 다음 Flow
              screenModel(): 지금 화면 제목·본문·버튼 ①~④ 이름·초상 표정
pibo.ts       파이보 얼굴 128×64 1비트 그림
```

- 엔진과 흐름은 **순수 함수**다(DOM·네트워크 없음). 난수 상태도 저장에 들어 있어 같은 입력이면 같은 결과.
- 화면은 `screenModel()`만 보고 그린다. 웹은 그 위에 블록 마을·초상을 얹은 것뿐이다.
- 테스트: `tests/growup-flow.test.ts`가 **화면 없이 버튼만 눌러** 졸업·엔딩까지 가는지 확인한다.

### 한 달의 흐름
```
town ─①~④─▶ place ─①~④─▶ month(4주) ─아무 버튼─▶ result
   ▲            │뒤로                                 │
   │            ▼                                     ▼
   └──── eventResult ◀─ event / quiz ◀─ review(학년 끝) ◀┘
졸업: graduation ─①~③─▶ ending
```

## 3. 기기 연동 약속

| 방향 | 방법 |
|---|---|
| 기기 → 게임 | 버튼: `window` 에 `CustomEvent('growup:input', { detail: { button: 1~4 \| 'back' } })` 또는 `flow.press()` 직접 호출 |
| 게임 → 기기 | `CustomEvent('growup:bridge')` — `screen`(화면 이름과 버튼 ①~④의 뜻), `turn`(결과·표정), `event`, `ending` |
| 파이보 얼굴 | `piboFace(expression)` → 128×64 1비트, `packRows()` → 1024바이트(행 우선, 한 바이트에 가로 8픽셀). 컨트롤러 메모리 배치 변환은 기기 쪽에서(사양 확인 필요) |
| 파이브레인 화면 | `screenModel()` 의 `title / lines / choices / portrait / hud` 를 240×320 에 맞춰 그린다(전용 렌더러는 아직 없음) |

'뒤로'를 파이브레인 버튼 4개로 어떻게 낼지(길게 누르기·두 버튼 동시)는 정해야 한다.

## 4. 초상

찾는 순서: 플레이어가 고른 것(표정별 → 학교급별 → 전체) → 개발자 폴더 → 픽셀 아바타.

- **프리셋** 6개(16×16 픽셀, 표정 5가지가 자동으로 바뀐다)
- **직접 그리기**: 16·24·32칸 픽셀 편집기(펜·지우개·채우기·색 집기·좌우 대칭·되돌리기)
- **그림 올리기**: png·jpg·webp, 세로 320px로 줄여 이 기기에 저장
- **개발자 폴더**: `src/games/growup/portraits/` 에 `elem-happy.png` 같은 이름으로 넣고 빌드(→ 폴더 README)
