# 꿈자람 마을(Dreamgrow Town) — 설계서

초1부터 고3까지 12년(144달)을 키워 진로를 정하는 육성 시뮬레이션.
**체험 앱 '로봇 놀이'(openpibo-os `kids/`)의 [키우기](다마고치)를 대신할 콘텐츠**로 만든다.
버튼 4개(①~④)만으로 끝까지 할 수 있고, 웹 화면 · 파이브레인(LCD 240×320) · 파이보(OLED 128×64)가 같은 엔진을 쓴다.

---

## 1. 포커스 교육 분야

### 한 줄로
**"나를 알고(자기 이해) → 일의 세계를 알고(직업 이해) → 선택과 결과를 잇는(의사결정·자기관리)" 진로교육**이 중심이고,
로봇 놀이의 **계산적 사고(CT)** 와는 "변수 관찰 · 조건 · 이벤트"로 이어 붙인다.

### 1-1. 중심 분야 4개

| # | 분야 | 아이가 하게 되는 생각 | 게임 장치 | 코드 |
|---|---|---|---|---|
| ① | **자기 이해** | "나는 무엇을 할 때 즐겁지?" "내 흥미 유형은?" | 학년마다 돌아보기 질문("올해 가장 즐거웠던 일은?") · 진로흥미 6유형(RIASEC) 그래프 · 이야기 들어 주기 | `engine.reflect`, `edu.riasec` |
| ② | **일과 직업세계 이해** | "이 직업은 무슨 일을 하지? 어떻게 되지? 무슨 과목이 필요하지?" | 직업 29개 카드(하는 일·되는 길·관련 과목·형태) · 직업 퀴즈(보기 4개) · 엔딩 도감 | `careers.ts`, `edu.makeQuiz` |
| ③ | **진로 탐색과 의사결정** | "이걸 고르면 무엇을 못 하지?" "닿지 못한 길엔 무엇이 모자랐지?" | 한 달에 하나만 고르는 선택(기회비용) · 학년마다 열리는 장소 14곳 · 졸업 리포트의 "조금만 더 했다면 닿았을 길" | `flow`, `edu.nearMisses` |
| ④ | **자기관리 · 경제 감각** | "쉬는 것도 계획이다" "들어온 돈과 쓴 돈" | 4주 진행(지치면 뒤 주가 흔들림) · 아파서 쉬는 달 · 용돈 기입장 · 창업에 필요한 모은 돈 | `engine.odds`, `YearStats` |

### 1-2. 곁가지 분야 2개

| 분야 | 장치 |
|---|---|
| 관계(사회정서) | 같은 관심사 친구 4명, 친구·단짝 사건, 10년 뒤 이야기. 순위·비교는 없다 |
| 디지털 표현 | 픽셀 초상 편집기(16·24·32칸, 좌우 대칭) — 내 캐릭터를 내가 그린다 |

### 1-3. 로봇 놀이(CT) 와 잇는 자리 — 키우기를 대신하므로 지켜야 할 것

로봇 놀이 설계(KIDS.md)는 키우기를 **개념 사다리 5~7칸(이벤트·변수 관찰·조건)의 재료**로 쓴다. 대체 게임도 이 자리를 비우지 않는다.

| 로봇 놀이 개념 | 키우기(지금) | 꿈자람 마을에서 |
|---|---|---|
| 5 이벤트 | "쓰다듬으면 → 인사춤" | "학년이 끝나면 → 돌아보기", "친구와 친해지면 → 친구 사건"(이미 있음). 2차: 아이가 직접 거는 규칙 |
| 6 변수 관찰 | `배고픔 = 6`, 20분 그래프 | 피로·스트레스·기분·용돈이 숫자로 보이고 4주마다 바뀐다. 학년 요약(들어온 돈·쓴 돈·남은 돈)이 관찰 일기 역할. 2차: 12년 그래프 |
| 7 조건 | "배고픔이 7보다 크면 → '밥 줘'" | 지치면 실패가 잦고 아프다(규칙을 몸으로 겪는다). 2차: **규칙 카드** "피로가 70보다 크면 → 집에서 쉬기"로 한 해를 자동 진행해 보기 |

### 1-4. 로봇 놀이 원칙과 맞추기 (KIDS.md 9절 "넣지 않는 것")

| 원칙 | 지금 상태 |
|---|---|
| 방치 벌점 없음 | **맞춤.** 키우기 모드에서 오래 안 와도 수치가 떨어지지 않는다(반갑게 맞기만, 이번에 고침) |
| 순위·속도 경쟁 없음 | 맞음. 점수판·시간 기록 없음. 별(등급)은 내 결과에만 붙는다 |
| 수치 관리 반복 없음 | 맞음. 돌보기 버튼만 누르는 화면이 없다. 수치는 선택의 결과로만 바뀐다 |
| 끌어 놓기 없음, 누르기만 | 맞음. 모든 진행이 버튼 ①~④(+뒤로) |
| 아이별 기록 | **아직 없음** — 지금은 브라우저 하나에 한 판. 로봇 놀이 프로필(번호+그림)을 받아 저장을 나누어야 한다 |
| 선생님 화면(차시·발문·도달 기록) | **아직 없음** — 아래 3절 |

### 1-5. 정확성 원칙
- 직업 카드는 일반적인 경로만 적는다. 퀴즈는 카드 내용에서만 문제를 만든다(새 사실을 지어내지 않는다).
- 퀴즈 오답은 다른 분야 직업·겹치지 않는 과목에서 고른다(정답이 둘처럼 보이지 않게).
- RIASEC 은 게임 활동으로 계산한 간이 유형이라고 화면에 밝힌다. 실제 검사는 커리어넷 등으로 안내.
- 교육과정 연계(창의적 체험활동 진로활동, 실과 등)는 문구를 넣기 전에 공식 문서로 확인한다 — **확인 필요**.

## 2. 대상과 읽기 부담

로봇 놀이 대상은 **초등 저학년 중심**이다. 이 게임은 글이 많다(활동 설명·사건·직업 카드).

- 지금 그대로면 **초등 3~6학년**이 맞다. 저학년이 하려면: 로봇이 화면 글을 읽어 주기(기기 TTS — 로봇 놀이 `make_voice.py` 방식으로 문장 미리 만들기), 문장 줄이기, 직업 수 줄이기.
- 1회 30~40분(한 번에 키우기) — 한 차시에 맞다. 키우기 모드는 교실보다는 가정용.

## 3. 수업용으로 더 할 것(제안)

| 항목 | 내용 |
|---|---|
| 차시 4개 | ① 나를 알기(1~3학년 플레이 + 돌아보기) ② 직업 알기(퀴즈·도감) ③ 선택과 결과(같은 시작으로 두 번 키워 비교) ④ 진로 리포트 발표 |
| 선생님 발문 | 차시마다 2~3개. 예: "쉬지 않았을 때 무슨 일이 생겼나요?" "닿지 못한 직업에 무엇이 모자랐나요?" |
| 도달 기록 | 로봇 놀이처럼 ○ 써 봤어요 / ◎ 스스로 했어요: 돌아보기 답함 · 퀴즈 n개 · 흥미 유형 확인 · 리포트 읽음. 점수·순위는 없다 |
| 아이별 저장 | 로봇 놀이 프로필 번호를 받아 `games:growup:<번호>:save` 처럼 나눈다 |

## 4. 엔진 구조

```
types.ts      상태(GameState)·보고서 자료형 — JSON 으로 저장된다(v4, 한 판 약 6KB)
calendar.ts   턴 → 학년·월·방학
data.ts       구역 4 · 장소 14(학년에 따라 열림) × 활동 4
careers.ts    직업 29개(하는 일·되는 길·10년 뒤 3단계·흥미 유형·관련 과목)
events.ts     사건 23개 / friends.ts 친구 4명과 친구 사건 8개
engine.ts     규칙: 4주 진행, 컨디션, 시험, 학년 정산, 사건, 퀴즈, 돌아보기, 진로 판정
edu.ts        교육 장치: RIASEC, 퀴즈 만들기, 돌아보기 조언, 모자란 것
flow.ts       ★ 진행 상태 기계: (Flow, GameState, 버튼) → 다음 Flow
              screenModel(): 지금 화면 제목·본문·버튼 ①~④ 이름·초상 표정
pibo.ts       파이보 얼굴 128×64 1비트 그림
```

- 엔진과 흐름은 **순수 함수**(DOM·네트워크 없음). 엔진만 묶으면 109KB(gzip 31KB), Node 에서 화면 없이 한 판이 끝난다.
- `tests/growup-flow.test.ts` 가 **화면 없이 버튼만 눌러** 졸업·엔딩까지 가는지 확인한다.

```
town ─①~④─▶ district ─①~④─▶ place ─①~④─▶ month(4주) ─아무 버튼─▶ result
   ▲            │뒤로                                 │
   └──── eventResult ◀─ event / quiz ◀─ review(학년 끝) ◀┘
졸업: graduation ─①~③─▶ ending
```

## 5. 기기 — 리포 문서 기준(실기기 확인 필요)

openpibo-os 리포 문서에 적힌 값이다. 데이터시트·실기기로 다시 확인할 것.

| | 파이브레인 | 파이보 |
|---|---|---|
| 본체 | Raspberry Pi 4 계열(문서에 "Pi 4 의 I2S"), 납품 메모리 2GB | 리눅스 기반(로봇 놀이와 같은 파이썬 서버가 돈다) |
| 화면 | LCD **ILI9341 240×320**, SPI0 + DC GPIO23 (`OledByPiBrain`). 방향은 확인 필요 | OLED **128×64** (`Oled`) |
| 입력 | 버튼 4개 직결 GPIO **4/17/27/26** pull-up (`get_button(1~4)`). 실제 위치 순서는 확인 필요 | PIR·터치·버튼(MCU 경유) |
| 로봇 놀이 키우기 | 버튼 1~4 = 밥·놀기·재우기·씻기, LCD 에 친구 그림 + 수치 세 줄 | 머리 터치 = 쓰다듬기 |

### 연결 방법(로봇 놀이 구조에 맞추기)
로봇 놀이는 **로봇의 FastAPI 서버(50060) + 태블릿 브라우저**다. 같은 모양으로:

1. **태블릿 화면**: 이 게임 빌드(정적 파일)를 로봇 서버가 그대로 서빙 — 외부 CDN·이미지 파일이 없어 AP(오프라인)에서도 된다.
2. **버튼 → 게임**: 서버가 `get_button` 을 읽어 태블릿에 알리고(로봇 놀이처럼 짧은 주기 GET), 화면은 `growup:input` 으로 넣는다.
3. **게임 → LCD/OLED**: 화면이 `screenModel()`·표정을 서버로 보내면, 서버가 PIL 로 LCD 를 그린다(로봇 놀이 `face.py` 방식). 파이보는 `piboFace()` 5장을 미리 PNG/바이트로.
4. **태블릿 없이 PiBrain 만으로**: 엔진을 서버에서 돌려야 한다 → 엔진을 파이썬으로 옮기거나(로봇 놀이 `pet.py` 처럼 "로봇·화면은 모른다") 기기에 Node 를 둔다.
   옮기려면 먼저 사건 조건(지금 JS 함수)을 JSON 조건식으로 바꾼다(`content.json` 방식).

### 확인 필요
- **교실 태블릿 브라우저 버전** — 로봇 놀이는 구형 브라우저 기준(ES5 + fetch)이다. 이 게임은 최신 문법(React·ES2020+)으로 빌드되므로, 구형이면 레거시 빌드가 필요하다.
- PiBrain 에서 '뒤로' 입력(길게 누르기·두 버튼 동시)
- 메모리 2GB 에서 목소리 모델(약 330MB)과 함께 돌릴 때 여유

## 6. 초상

찾는 순서: 플레이어가 고른 것(표정별 → 학교급별 → 전체) → 개발자 폴더 → 픽셀 아바타.

- **프리셋** 6개(16×16 픽셀, 표정 5가지가 자동으로 바뀐다)
- **직접 그리기**: 16·24·32칸 픽셀 편집기(펜·지우개·채우기·색 집기·좌우 대칭·되돌리기)
- **그림 올리기**: png·jpg·webp, 세로 320px로 줄여 이 기기에 저장
- **개발자 폴더**: `src/games/growup/portraits/` 에 `elem-happy.png` 같은 이름으로 넣고 빌드(→ 폴더 README)
